# make-knowledge-cards

把粘贴的文本或本地 Markdown/TXT 文件，转换成 5–8 张真正值得复习的知识卡片。

一个纯指令的 Agent Skill：逻辑全部写在 `SKILL.md` 里，不需要脚本、API Key 或第三方库。

## 1. 解决的问题

读论文、教程、长文或笔记时，常见的困境是：

- 读完了，但过几天只记得零散印象；
- 让 AI 总结，得到的是一份“全文缩写”，重点不突出；
- 自己整理卡片耗时，而且容易重复、遗漏；
- 普通摘要可能混入原文没有的例子、数字或结论。

`make-knowledge-cards` 不追求概括全文，而是先判断哪些知识真正重要，再把每个知识点写成一张可复习的卡片。它把“读过”变成“记住并自测”。

## 2. 主要功能

| 能力 | 说明 |
| --- | --- |
| 输入 | 粘贴文本；本地 `.md` / `.txt` 文件 |
| 输出数量 | 目标 5–8 张；独立知识点不足时输出更少并注明；超过 8 个时保留最重要的 8 个 |
| 卡片结构 | 标题、核心知识、简明解释、例子或自测 |
| 知识提取 | 重要性筛选；一张卡只讲一个点；合并重复、从属和同义内容 |
| 事实约束 | 只使用原文信息，不编造例子、数字或结论 |
| 类型适配 | 科普、技术文档、新闻、观点评论等不同文章类型 |
| 语言 | 默认跟随原文语言；也可在请求中指定其他语言（如中文、英文） |
| 输入边界 | 不支持网页 URL、PDF/DOCX、图片/音频、Anki 导出、图形界面 |
| 依赖 | 无运行时脚本、无模型 API、无第三方库 |

每张卡片固定包含四部分：

| 字段 | 内容 |
| --- | --- |
| 标题 | 这张卡讲的具体知识点 |
| 核心知识 | 一句话说清一个结论 |
| 简明解释 | 2–4 句解释含义、原因或作用 |
| 例子 / 自测 | 原文中的具体例子，或一道答案可在原文中找到的自测题 |

## 3. 安装方法

本项目按 Agent Skills 的目录结构组织：一个技能一个文件夹，至少包含 `SKILL.md`，可附带 `agents/` 元数据。

```text
.
├── LICENSE
├── README.md
└── skills/
    └── make-knowledge-cards/
        ├── SKILL.md
        └── agents/
            └── openai.yaml
```

安装步骤：

1. 下载或复制本仓库到本地。
2. 将 `skills/make-knowledge-cards` 整个目录放入客户端使用的 skills 目录。
3. 如果客户端支持扫描路径，也可以直接把本仓库的 `skills/` 目录加入扫描路径。
4. 刷新或重启客户端；支持技能列表的客户端会显示 `Knowledge Card Maker`（技能名为 `make-knowledge-cards`）。

不同客户端的 skills 目录位置不同，请以客户端文档为准；本仓库不绑定特定客户端。

不需要 `pip install`、`npm install` 或配置 API Key。`agents/openai.yaml` 只提供客户端展示用的名称、简介和默认 prompt，不参与卡片生成逻辑。

安装后可以用一个短文本验证触发：

```text
用 make-knowledge-cards 把这句话做成知识卡片：光合作用把光能转化为化学能，主要发生在叶绿体中。
```

如果 Skill 正常工作，应看到符合格式的卡片，并附一行说明原文信息不足，而不是硬凑 5 张。

## 4. 使用方法

Skill 会根据 `description` 自动触发；也可以显式点名。支持以下三种常见用法。

### 4.1 转换粘贴的文本

```text
用 make-knowledge-cards 把下面这段内容做成知识卡片：

<粘贴正文>
```

### 4.2 转换本地文件

```text
把 notes/sleep.md 转成知识卡片。
```

支持 `.md` 和 `.txt`。路径可以是相对路径或绝对路径；Skill 会先读完整文件，再提取知识点。

### 4.3 指定输出语言

默认跟随原文语言。需要其他语言时，直接在请求里说明：

```text
把这篇英文论文做成中文知识卡片。
```

卡片正文使用指定语言，`Core idea`、`Explanation`、`Example / self-check` 等字段标签保持英文。

### 4.4 数量与边界

- 目标是 5–8 张；独立知识点不足 5 个时，输出实际数量，并注明“未做填充”。
- 超过 8 个知识点时，保留最重要的 8 个。
- 遇到 URL、PDF、DOCX、图片/音频、Anki 或 GUI 请求时，Skill 会说明不支持，并请你粘贴正文或提供 `.md`/`.txt` 文件。

## 5. 输入输出示例

### 输入

```text
请把这段文字做成知识卡片：

咖啡因不提供能量。清醒时腺苷不断积累，与受体结合产生困意；咖啡因抢先占据腺苷受体，阻断困倦信号。咖啡因半衰期约五小时，下午三点后喝可能影响夜间睡眠。长期大量摄入会让腺苷受体增多，需要更多咖啡才有效，这就是耐受。突然停咖啡，新增受体让腺苷更易结合，出现头痛、疲倦等戒断症状，通常在停咖啡后十二到二十四小时出现。咖啡因不能替代睡眠，它只屏蔽困意，不能清除腺苷，也不能完成睡眠才能完成的记忆巩固和废物清理。
```

### 输出

```markdown
**Source:** pasted text · **Cards:** 5

### 1. 咖啡因靠抢占腺苷受体提神

**Core idea:** 咖啡因不提供能量，它靠抢先占据腺苷受体来阻断困倦信号。

**Explanation:** 清醒时腺苷不断积累，与受体结合后产生困意。咖啡因先占据受体，使腺苷无法传递“该休息了”的信号。

**Example / self-check:** Self-check: 咖啡因提神的核心机制是什么？—— 抢先占据腺苷受体，阻断腺苷的困倦信号。

### 2. 半衰期约五小时，决定喝咖啡的时间

**Core idea:** 咖啡因的半衰期约为五小时，摄入时间会影响夜间睡眠。

**Explanation:** 喝下咖啡五小时后，体内仍有一半左右的咖啡因在起作用。下午三点以后喝，到睡觉时可能仍有明显残留。

**Example / self-check:** Example (from source): 下午三点以后喝咖啡，可能到晚上睡觉时仍有明显残留。

### 3. 长期摄入导致腺苷受体增多与耐受

**Core idea:** 长期大量摄入咖啡因会使腺苷受体增多，同样剂量能占据的比例下降，从而产生耐受。

**Explanation:** 受体变多后，人需要更多咖啡因才能获得同样的清醒感。原文把这种身体补偿称为咖啡因耐受。

**Example / self-check:** Self-check: 为什么长期大量喝咖啡会觉得咖啡“不管用了”？—— 腺苷受体增多，同剂量咖啡因能占据的比例下降。

### 4. 突然停咖啡会引发戒断症状

**Core idea:** 突然停咖啡时，新增的腺苷受体让腺苷更易结合，出现头痛、疲倦、注意力下降等戒断症状。

**Explanation:** 这些症状通常在停咖啡后十二到二十四小时出现，持续几天后缓解。原文指出，“不喝咖啡就头疼”往往不是咖啡在起作用，而是身体已经适应了它。

**Example / self-check:** Self-check: 咖啡因戒断症状通常在停咖啡后多久出现？—— 十二到二十四小时。

### 5. 咖啡因不能替代睡眠

**Core idea:** 咖啡因不能替代睡眠：它只暂时屏蔽困意，不能清除腺苷。

**Explanation:** 它也不能完成睡眠才能完成的记忆巩固和代谢废物清理。因此咖啡因只是掩盖困意，不能替代睡眠本身的功能。

**Example / self-check:** Self-check: 咖啡因能清除体内积累的腺苷吗？—— 不能，它只暂时屏蔽困意信号。
```

## 验证

项目使用官方 [skill-creator](https://github.com/openai/skills/tree/main/skills/.system/skill-creator) 的 `init_skill.py` 初始化，并通过其 `quick_validate.py` 校验。在仓库根目录运行（将路径替换为实际的 skill-creator 位置）：

```text
$ python /path/to/skill-creator/scripts/quick_validate.py skills/make-knowledge-cards
Skill is valid!
```

测试覆盖中文科普、英文技术文档、中文新闻、观点评论、短文本，以及 URL 等不支持输入的拒绝路径。
